# Payment slip → branded confirmation bot

A Telegram bot for a group. When someone posts a bank/UPI payment slip — photo,
image file (JPG/PNG/WEBP/HEIC) or PDF — the bot:

1. reads the fields off it with an OpenAI vision model — works across bank/app layouts;
2. renders a **company-branded payment confirmation** image;
3. replies to the original slip with that image.

## What it extracts

account holder (beneficiary) name · account number · IFSC code · bank name ·
amount · date · time · UTR / transaction / reference number · transfer mode ·
status.

Values are copied verbatim. Anything not printed on the slip is left blank and
listed in the reply ("Not found on source slip: …"). The bot never fills in or
corrects a missing value.

## Design of the output

The generated image is deliberately **your** document, not a copy of a bank
screen: your name/logo is the largest element, and a fixed footer states it is a
confirmation generated by your company (not a bank-issued document) and tells the
reader to verify the UTR with their bank. Colours, logo and text come from `.env`.
Run `python preview.py` to see it with sample data and tweak `slip_renderer.py`.

## Setup

Requires Python 3.11+.

```bash
cd telegram-slip-bot
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env      # then fill it in
```

### .env

| var | notes |
|---|---|
| `TELEGRAM_BOT_TOKEN` | from [@BotFather](https://t.me/BotFather) |
| `OPENAI_API_KEY` | platform.openai.com — needs credits on the account |
| `EXTRACTION_MODEL` | `gpt-4o-mini` (default, cheap) or `gpt-4o` (more accurate). |
| `ALLOWED_CHAT_IDS` | optional allowlist. Empty = every group the bot is in. `/id` in a group prints its id. |
| `MAX_CONCURRENCY` | extraction calls in flight at once |
| `COMPANY_*`, `BRAND_*` | branding on the confirmation image |

### Telegram

1. `@BotFather` → your bot → **Bot Settings → Group Privacy → Turn off**.
   Without this the bot cannot see photos posted in the group.
2. Add the bot to the group (member is enough; admin also fine).

### Fonts (recommended)

Drop `Inter-Regular.ttf`, `Inter-Medium.ttf`, `Inter-Bold.ttf` into
`assets/fonts/` for the cleanest type. Without them the renderer falls back to
DejaVu / Liberation / Arial / a bundled default, in that order. Put your logo at
`assets/logo.png` (or point `COMPANY_LOGO` elsewhere).

## Run

```bash
python bot.py
```

Long-polling — no public URL or webhook needed. For a server, run it under
systemd / `pm2` / Docker and keep it restarting.

### Rough cost (extraction only, ~2,500 slips/day)

Each slip ≈ one high-detail image + ~0.2k output tokens.

| model | ≈ /day | ≈ /month |
|---|---|---|
| gpt-4o-mini | $1–2 | $30–60 |
| gpt-4o | $15–20 | $450–600 |

Start on `gpt-4o-mini`, check accuracy on your real slips, move to `gpt-4o` only
if needed. The OpenAI account must have credits (Billing → Add to credit balance).

## Files

| file | role |
|---|---|
| `bot.py` | Telegram handlers, entry point |
| `extractor.py` | image → structured fields (OpenAI vision) |
| `models.py` | the field schema + "is this really a slip" check |
| `slip_renderer.py` | fields → branded PNG (Pillow) |
| `config.py` | env / .env loading |
| `preview.py` | render a sample (or run extraction on a local image) offline |

## Limitations / notes

- Photos, image files (JPG/PNG/WEBP/HEIC/BMP/TIFF) and PDF. PDFs are rasterised
  page by page (first 4 pages) and the first page that reads as a slip is used.
- One slip per message. Albums are handled as separate messages.
- If extraction fails or the image isn't a slip, the bot replies with a short
  error instead of an image.
